# Ledger Design System: "Academic Precision"

## 1. Design Philosophy
Ledger is not a generic consumer app; it is a serious analytical tool that handles complex statistical adjudication. The design must reflect **trust, precision, and clarity**. 

**Core Tenets:**
- **Do Not Distract:** The data and the ledger entries are the heroes. 
- **No Generic Dark Mode:** Avoid the standard "hacker" neon-on-black theme. Instead, we use a highly refined, premium light theme (inspired by Stripe and Vercel's clean aesthetic) that feels like reading a beautifully typeset academic paper.
- **Typographic Hierarchy:** Information density is managed through font weights and subtle color contrast, not heavy boxes or borders.
- **Honest UI:** When a hypothesis fails, it is not hidden; it is elegantly crossed out or muted, showing the system's rigor.

## 2. Color Palette
A minimalist, high-contrast light theme using subtle cool greys and highly semantic accents.

### Base Colors
- **Background:** `Pearl White (#FCFCFD)` - Soft on the eyes, not glaringly bright.
- **Surface/Cards:** `Pure White (#FFFFFF)` - With very subtle, soft shadows for depth (Glassmorphism sparingly used for floating elements).
- **Primary Text:** `Ink Black (#0F172A)` - Deep blue-grey for maximum readability.
- **Secondary Text:** `Slate Grey (#64748B)` - For metadata, timestamps, and rejected hypotheses.
- **Borders/Dividers:** `Muted Silver (#E2E8F0)` - Ultra-thin, 1px solid lines.

### Semantic Accents (Used Sparingly)
- **Primary Action (Brand):** `Deep Royal Blue (#1E3A8A)` - For primary buttons and active states.
- **Supported / Success:** `Emerald Green (#059669)` - For p < 0.05, hypothesis supported, tests passed.
- **Rejected / Failed:** `Crimson Red (#E11D48)` - For unsupported claims, failed assumptions, or Adversary (Red Team) flags.
- **Warning / Caveat:** `Amber (#D97706)` - For statistical caveats (e.g., "small sample size warning").

## 3. Typography
Modern, highly legible, and structured.

- **UI & Prose Font:** `Geist` or `Inter` (Sans-serif)
  - Weights: 400 (Regular) for body, 500 (Medium) for labels, 600 (Semi-bold) for headings.
  - Line height: 1.6 for prose, ensuring readability of long reports.
- **Data & Code Font:** `Geist Mono` or `JetBrains Mono`
  - Used for variables, p-values, Python/Pandas code snippets, and ledger JSONs.
  - Style: Slightly smaller (0.9em), padded, with a faint grey background (`#F1F5F9`).

## 4. UI Components

### 4.1 The Ledger Card (The core unit of UI)
A clean, expanding accordion that represents a single hypothesis.
- **Collapsed State:** Shows the Hypothesis ID (e.g., `H07`), the plain-text statement, and a clean tag (`SUPPORTED` in Green or `REJECTED` in Slate).
- **Expanded State:** Reveals the deterministic "Receipt":
  - The Pandas code executed (in a beautiful syntax-highlighted block).
  - Assumption checks (e.g., *Normality: Passed*).
  - Test selected, effect size, and FDR-adjusted p-value.
  
### 4.2 Streaming Analysis Interface (The Loading State)
Instead of a generic spinner, the user sees a real-time, terminal-like feed (styled beautifully, not like a raw CMD prompt):
> `[Agent 1] Profiling 34 columns...`
> `[Agent 2] Proposing 12 testable hypotheses...`
> `[Agent 3] Freezing ledger...`
> `[Agent 4] Executing test for H01...`

### 4.3 The Final Report
Looks like a modern digital article. 
- A clean, centered column of text (max-width: 65ch for readability).
- Inline charts rendered flawlessly, with captions tied back to the specific Ledger ID.
- Any sentence generated by the Reporter (A6) has a subtle, dotted underline. Clicking it opens the Ledger Card that licenses that sentence.

## 5. Animations & Micro-interactions
- **Minimalist Motion:** No bouncy or flashy animations. Use smooth, fast fades (`150ms ease-in-out`) for opening accordions or tooltips.
- **Data Appearance:** When charts load, they should cleanly fade in, not bounce. 

## 6. Accessibility
- All text meets WCAG AAA contrast ratios.
- Semantic HTML used throughout for screen reader compatibility.
- Colors are supplemented with icons (e.g., a green checkmark `✓` or red cross `✗`) for colorblind users.
