# Ledger Architecture & Agentic Pipeline

## 1. System Overview
Ledger is a robust, multi-agent AI data analyst designed for statistical rigor, built on a highly scalable cloud architecture. 
Unlike typical "chat-with-CSV" tools that suffer from severe hallucination and p-hacking, Ledger enforces statistical discipline through a strictly ordered, hand-written state machine.

### Tech Stack
- **Frontend:** React + Vite (Deployed on Vercel) - Handles the streaming UI and interactive reports.
- **Backend/Execution Engine:** FastAPI (Deployed on Render) - Manages the agent state machine, data processing (Pandas), and secure execution.
- **LLM Inference:** Groq (primary for blazing fast inference) & Gemini.
- **Observability & Telemetry:** Langfuse / Custom PostgreSQL logging for the Self-Improving Loop.

## 2. The Core Agentic Pipeline (The Forward Pass)
The pipeline is a fixed state machine. An ordering constraint enforces that hypotheses are frozen (A3) before any code executes (A4), making post-hoc selection structurally impossible.

### A0: The Data Janitor (LLM + Heuristics)
*New Feature*
- **Role:** Ingests raw, messy CSVs. Handles missing value imputation, date parsing, and type coercion before analysis begins.
- **Nature:** Hybrid (Deterministic Pandas + LLM for semantic type guessing).

### A1: The Profiler
- **Role:** Generates marginal summaries (Types, cardinality, distributions, missingness) for every column.
- **Nature:** **Fully Deterministic** (No LLM). This ensures the LLM doesn't peek at the data to game the hypotheses.

### A2: The Proposer
- **Role:** Reads the A1 profile and proposes testable hypotheses in natural language. (Can also accept *User-defined Natural Language Hypotheses*).
- **Nature:** **LLM (Groq/Gemini)**.

### A3: The Registrar
- **Role:** Freezes the proposed hypotheses. The registry becomes immutable. If it isn't registered here, it cannot be reported later.
- **Nature:** **Fully Deterministic**.

### A4: The Executor (with Repair Loop)
- **Role:** Writes Pandas code to execute the tests for registered hypotheses. Runs in a sandboxed environment on the Render backend. If the code crashes, A4 enters a self-repair loop (up to 3 tries) by reading the Python traceback.
- **Nature:** **LLM**.

### A5: The Statistician
- **Role:** The ultimate arbiter of truth. Checks statistical assumptions (e.g., Normality via Shapiro-Wilk) and selects the appropriate test (e.g., Welch's t vs Mann-Whitney U). Computes effect sizes and applies session-wide Benjamini-Hochberg False Discovery Rate (FDR) correction.
- **Nature:** **Fully Deterministic**. 

### A6: The Reporter
- **Role:** Writes the final, readable prose report. 
- **Constraint:** Can *only* use sentences backed by a `licensed_text` field generated by A5. Any unbacked sentences are structurally rejected.
- **Nature:** **LLM**.

### A7: The Adversary (Red Team)
*New Feature*
- **Role:** Critiques A6's report before the user sees it. Looks for causal language where only correlation was proven, or overstated effect sizes. Forces A6 to rewrite if violations are found.
- **Nature:** **LLM**.

## 3. The Markout Feature: The Self-Improving Agentic Loop (A8 Meta-Agent)

Ledger is not static. It learns from its own execution history using an observability-driven Meta-Agent loop. This is the standout engineering feature of the project.

### Phase 1: High-Fidelity Observability (Telemetry)
Every session logs dense telemetry to a database:
- User natural language inputs.
- Hypotheses proposed by A2.
- The exact Pandas code generated by A4, including failed attempts and error traces.
- The rejection rate of hypotheses by the Deterministic Statistician (A5).
- The critiques raised by the Red Team (A7).

### Phase 2: Periodic Reflection (A8 Meta-Agent)
Running on a scheduled background task (or triggered offline), the A8 Meta-Agent analyzes the telemetry logs to detect systemic weaknesses in the forward pipeline.

### Phase 3: Dynamic System Improvement
The Meta-Agent implements structural improvements without human intervention:

1. **Prompt Template Evolution (Self-Healing Code):** 
   - *Example:* If A8 notices that A4 consistently fails at processing `datetime` columns in Pandas across 50 different user sessions, it extracts the successful repair patterns. A8 then automatically updates A4's system prompt to include a new rule: *"Always use `pd.to_datetime(..., coerce=True)` for temporal columns."*

2. **Hypothesis Quality Calibration:**
   - *Example:* If A8 notices that A5 (Statistician) rejects 90% of hypotheses related to columns with high cardinality (like IDs), A8 updates the A2 (Proposer) context window to penalize hypotheses involving high-cardinality non-categorical columns, improving the FDR power over time.

3. **Adversarial Strengthening:**
   - Over time, A7's successful critiques are fed back into A6's training context, making the initial report generation safer and more statistically precise.

By turning local failures into global prompt updates, the Ledger system functionally *writes better code and proposes better hypotheses tomorrow than it did today*.
